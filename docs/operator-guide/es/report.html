Resumen

Qué hace nsconv

Los switches y routers Huawei exportan sus flujos como NetStream: NetFlow v5, NetFlow v9 o IPFIX con particularidades de Huawei (un campo de versión v5 modificado, campos privados, marcas de tiempo relativas al uptime, intervalos largos de refresco de plantillas, tasas de muestreo que a menudo no se informan). Illumio FlowLink lee NetFlow v5, v7, v9, IPFIX y sFlow1. nsconv se ubica entre ambos: recibe NetStream, lo decodifica resolviendo las particularidades de Huawei y vuelve a enviar cada flujo como IPFIX estándar y limpio (por defecto), NetFlow v9 o NetFlow v5 a FlowLink.

Use nsconv cuando equipos Huawei deban alimentar a Illumio FlowLink. Corre como un servicio pequeño (nsconv.service) en el equipo de FlowLink o en un equipo propio. Un único binario, nsconvctl, ejecuta el servicio y es también la herramienta de línea de comandos y la interfaz de terminal.

Flujo de datos, despliegue en el mismo equipo (por defecto)

Qué ocurre con cada flujo

  • Solo se acepta de switches autorizados. Los datagramas de orígenes fuera de la lista allow de la entrada se descartan y se cuentan. Una lista vacía descarta todo.
  • Se decodifica resolviendo las particularidades de Huawei: v5 con el bit de dirección, plantillas v9 e IPFIX por switch, Source ID por tarjeta de línea, tiempos IPFIX relativos al uptime, campos repetidos. Las plantillas aprendidas se guardan, de modo que un reinicio no espera el próximo refresco de plantillas del switch.
  • Se reenvía con una plantilla fija y estándar (solo campos IANA, sin relleno, sin campos de fabricante), marcas de tiempo absolutas, el conteo de bytes y la tasa de muestreo en cada registro. Los contadores no se escalan: FlowLink recibe los números originales y la tasa.
  • Se conserva la identidad del exportador. Por defecto los flujos de cada switch salen de nsconv desde la IP y el puerto de ese switch, de modo que FlowLink sigue viendo cada switch como un emisor propio.
  • Corrección de reloj. Si el reloj de un switch difiere en más de 5 minutos (zona horaria, sin NTP), los tiempos de los flujos se corrigen a la hora de recepción para que FlowLink no los descarte.
  • Todo se cuenta. Cada flujo descartado o modificado tiene un contador con nombre en nsconvctl status, la TUI y el journal.

Firewall (firewalld)

Abra el puerto de entrada solo para los switches, en una zona dedicada. El nombre de la zona y la red son ejemplos:

EQUIPO DE INSTALACIÓN (ROOT)
firewall-cmd --permanent --new-zone=nsconv-exporters
firewall-cmd --permanent --zone=nsconv-exporters --add-source=198.51.100.0/24
firewall-cmd --permanent --zone=nsconv-exporters --add-port=9996/udp
firewall-cmd --reload

Si FlowLink corre en el mismo equipo y solo nsconv debe alimentarlo, mantenga el puerto de FlowLink (4739) cerrado hacia la red. El tráfico de nsconv a FlowLink queda en loopback.

SELinux

No se necesita ningún módulo de política. Un binario en /usr/bin o /usr/local/bin tiene la etiqueta bin_t y systemd lo ejecuta en el dominio unconfined_service_t2. Si copia el binario a mano desde otro directorio, restaure su etiqueta; una etiqueta incorrecta aparece como estado 203/EXEC en systemctl status nsconv:

EQUIPO DE INSTALACIÓN (ROOT)
restorecon -v /usr/local/bin/nsconvctl

Configurar nsconv

Configurar nsconv

La configuración es un archivo TOML, /etc/nsconv/nsconv.toml, con un [[input]] (adonde envían los switches) y uno o más [[output]] (adonde van los flujos). El archivo incluido tiene una entrada llamada huawei y una salida llamada flowlink; las claves se escriben como input.huawei.allow, output.flowlink.target, etc. La lista completa de claves está en la sección Referencia.

nsconvctl config set cambia un valor, conserva los comentarios del archivo, valida el resultado, lo escribe y pide al servicio en ejecución que recargue. Un valor inválido se rechaza y el archivo no se toca.

PRIMER INICIOTres ajustes y arrancar
1

Autorice los switches

IP individuales o CIDR. Mientras no se defina, se descarta cada datagrama.

ROOT
nsconvctl config set input.huawei.allow '["198.51.100.0/24"]'
2

Apunte la salida a FlowLink

El valor por defecto es el consumidor IPFIX de FlowLink en el mismo equipo. Para un FlowLink en otro equipo use su dirección, por ejemplo 192.0.2.10:4739.

ROOT
nsconvctl config set output.flowlink.target 127.0.0.1:4739
3

Inicie el servicio y verifíquelo

Salud ok y un flows_out creciente indican que los flujos salen de nsconv.

ROOT
systemctl enable --now nsconv
nsconvctl status

Cambios habituales

ObjetivoComando (root)
Varias redes de switchesnsconvctl config set input.huawei.allow '["198.51.100.0/24", "203.0.113.5"]'
Muestreo 1:2048 no informadonsconvctl config set input.huawei.sampling_rate 2048
Un switch muestrea distintonsconvctl config set input.huawei.sampling_override '{ "198.51.100.21" = 2048 }'
Enviar NetFlow v9 en vez de IPFIXnsconvctl config set output.flowlink.protocol netflow9
Una sola copia del tránsitonsconvctl config set convert.direction ingress
Aceptar también switches IPv6nsconvctl config set input.huawei.listen '[::]:9996' y luego systemctl restart nsconv

Los contadores no se escalan; nsconv reenvía la tasa. Precedencia por switch: sampling_override, la tasa que informa el switch, luego sampling_rate (por defecto 1000).

Recargar o reiniciar

config set recarga por sí solo. Tras editar el archivo a mano o con nsconvctl config edit, ejecute nsconvctl reload. La dirección de escucha o el búfer de una entrada, agregar o quitar entradas y la sección [daemon] requieren systemctl restart nsconv (la recarga responde restart required). nsconvctl config check valida un archivo sin aplicarlo.

Una segunda salida

Las salidas se agregan en el archivo, p. ej. NetFlow v9 a otro colector (valores de ejemplo):

/etc/nsconv/nsconv.toml
[[output]]
name = "collector2"
protocol = "netflow9"
target = "192.0.2.20:2055"
source_address = "local"

Configurar FlowLink

Configurar FlowLink

FlowLink lee /etc/illumio-flowlink/config.yaml1. Agregue un consumidor para nsconv: un parser ipfix con un conector udp en el puerto de output.flowlink.target. remote_addrs es opcional, admite direcciones IP individuales (sin CIDR) como texto o lista, y limita el consumidor a esos orígenes2,3.

Mismo equipo, source_address = "exporter" (por defecto)

FlowLink ve a los switches como emisores, por lo que remote_addrs lista las IP de los switches (ejemplos):

/etc/illumio-flowlink/config.yaml
consumers:
  - name: nsconv-ipfix
    parser:
      type: ipfix
    connectors:
      - type: udp
        properties:
          ports: '4739'
          remote_addrs: '198.51.100.21,198.51.100.22'

source_address = "local"

FlowLink ve a nsconv como único emisor. En el mismo equipo: remote_addrs: '127.0.0.1'. Independiente: la IP del equipo de nsconv, por ejemplo remote_addrs: '192.0.2.30'.

Salida NetFlow v9 o v5

Con protocol = "netflow9" o "netflow5" use un consumidor con parser: type: netflow en un puerto propio (por ejemplo 2055) y ajuste output.flowlink.target a ese puerto. Mantenga un protocolo por consumidor y puerto.

Aplique el cambio reiniciando FlowLink1:

EQUIPO DE FLOWLINK (ROOT)
systemctl stop illumio-flowlink
systemctl start illumio-flowlink
Después de reiniciar FlowLink
nsconv reenvía sus plantillas cada 20 segundos (template_refresh_secs). Un colector que arranca después de nsconv decodifica los flujos a partir del siguiente refresco de plantillas.

Qué versión de NetStream usar en el switch

Tráfico del switchExportación del switchSalida de nsconv
Solo IPv4NetFlow v5 alcanza; v9 también funcionaipfix (por defecto)
IPv4 e IPv6NetFlow v9 (o IPFIX), más las líneas ipv6 netstream; NetStream v5 no transporta IPv6ipfix o netflow9; nunca netflow5

Defina input.huawei.sampling_rate (o sampling_override por switch) con la tasa configurada en los switches; los switches v5 normalmente no la informan.

Configurar Huawei

Configurar los switches Huawei

Comandos del equipo: verifique en su versión de VRP
Las líneas siguientes se ejecutan en el equipo Huawei, no en el equipo Linux. La sintaxis cambia entre familias de producto y versiones de VRP; contraste cada línea con la referencia de comandos de su modelo y versión antes de aplicarla.

Recomendaciones para todas las familias: enviar al equipo de nsconv (ejemplo 192.0.2.10) por UDP 9996; refrescar las plantillas cada minuto (template timeout-rate 1); envejecer los flujos rápido (timeout active 1, timeout inactive 15), de lo contrario los flujos largos llegan a FlowLink hasta 30 minutos tarde; usar índices de interfaz de 32 bits (index-switch 32); muestrear solo la entrada, para que el tráfico de tránsito no se informe dos veces; mantener el reloj del equipo con NTP y la zona horaria correcta. El timeout activo por defecto es de 30 minutos y el refresco de plantillas por defecto también es de 30 minutos1. Valores de ejemplo: dirección del switch 198.51.100.21, interfaces GigabitEthernet0/0/1 y 10GE1/0/1, nombre de registro illumio-rec, slot 3.

Serie S / AR (estilo V200): flujos originales NetFlow v9

EQUIPO HUAWEI — VERIFIQUE EN SU VERSIÓN DE VRP
ip netstream export version 9
ip netstream export source 198.51.100.21
ip netstream export host 192.0.2.10 9996
ip netstream export template timeout-rate 1
ip netstream export template option sampler
ip netstream export index-switch 32
ip netstream timeout active 1
ip netstream timeout inactive 15
#
interface GigabitEthernet0/0/1
 ip netstream sampler fix-packets 1000 inbound
 ip netstream inbound

Para switches solo IPv4 también sirve export version 5. En los routers AR un muestreador sin definir equivale a 1:100. Donde IPv6 deba verse, agregue las líneas ipv6 netstream equivalentes (mismas palabras clave, como en el ejemplo de NetEngine) y mantenga la versión 9.

Operación

Operación

Estado

nsconvctl status muestra la salud y sus motivos, las alertas abiertas, las entradas, los contadores (los contadores de descarte en cero se ocultan), una línea por sesión de exportador y una por salida. --exporter 198.51.100.21 lo limita a un switch, --detail agrega las interfaces con más tráfico y las sesiones inactivas, --json imprime el estado completo en JSON. Cada comando termina con una línea legible por máquina NSCONV-RESULT y un código de salida (sección Referencia). Extracto de una prueba de laboratorio que reprodujo capturas Huawei grabadas en un solo equipo, sin ningún colector escuchando:

  sampling-default:127.0.0.1:65009:0
      sampling rate not reported, using default 1000
  ...
counters
  COUNTER             VALUE

La tabla de exportadores tiene una fila por sesión de exportador con las columnas EXPORTER (IP y puerto de origen del switch), SOURCE-ID, VER (v5, v9, ipfix), INPUT, SAMPLING (tasa y su origen: override, reported por el switch o default), SKEW (reloj del switch menos reloj del equipo), RESTAMPED, FLOWS, NO-TPL, LAST SEEN y SEQ LOSS (pérdida estimada a partir de los números de secuencia del switch).

Alertas

Las condiciones que conviene revisar generan una alerta con un id estable: sampling-default, restamped, no-template, seq-gap (los números de secuencia muestran pérdida), many-sessions, flowless-sessions y collector-down (nada escucha en un destino local de salida). Una vez revisada, silénciela; vuelve si su valor se duplica o después de 24 horas sin la condición. Silenciar nunca cambia la salud.

ROOT O GRUPO NSCONV
nsconvctl dismiss sampling-default:198.51.100.21:40000:0
nsconvctl dismiss all
nsconvctl undismiss sampling-default:198.51.100.21:40000:0

Logs

nsconv escribe en el journal; journald se encarga de la rotación. En info no se registra nada por datagrama; las condiciones repetidas tienen límite de frecuencia y las persistentes (tasa de muestreo por defecto, desfase de reloj, datos sin plantilla) avisan una vez por exportador cada 6 horas.

ROOT O GRUPO NSCONV
nsconvctl logs -f                # seguir (journalctl -u nsconv -f)
nsconvctl logs --since 2h
nsconvctl logs --recent 50       # últimas líneas en la memoria del servicio
nsconvctl config set log.level debug   # una línea por tipo de evento, con límite (root)
nsconvctl config set log.level info

Capturar un switch para análisis

nsconvctl debug-capture 198.51.100.21 ejecuta tcpdump (root) durante hasta 60 segundos o 2000 datagramas y guarda en un archivo pcap los datagramas NetStream originales del switch; --dry-run muestra el comando tcpdump. nsconvctl decode <archivo.pcap> muestra los flujos que nsconv lee de él, en cualquier equipo.

Actualizar

RPM: rpm -Uvh con el paquete nuevo, por ejemplo rpm -Uvh nsconv-0.1.1-1.x86_64.rpm. La actualización conserva /etc/nsconv/nsconv.toml y las plantillas aprendidas, y reinicia el servicio si estaba en ejecución. Instalación del binario: ejecute install --now con el binario nuevo.

Desinstalar

RPM: rpm -e nsconv detiene y deshabilita el servicio y elimina los archivos; se conservan el usuario nsconv, /var/lib/nsconv y una configuración modificada (nsconv.toml.rpmsave). Instalación del binario: nsconvctl uninstall, o nsconvctl uninstall --purge para eliminar también /etc/nsconv, /var/lib/nsconv y el usuario y el grupo.

Recorrido TUI

Recorrido por la TUI

nsconvctl tui es una vista de terminal a pantalla completa del servicio en ejecución: el estado se actualiza cada segundo. Ejecútela como root (sudo nsconvctl tui) para editar la configuración en la pestaña Config; los miembros del grupo nsconv obtienen una vista de solo lectura. --lang es muestra las explicaciones en español (las etiquetas quedan en inglés), --theme brand|terminal|light|mono elige los colores y nsconvctl tui --demo funciona con datos de demostración y sin servicio, como en las pantallas siguientes (datos de demostración, direcciones de ejemplo).

Problemas

Solución de problemas por síntoma

Empiece con nsconvctl status: los motivos de salud, las alertas y los contadores de descarte distintos de cero suelen indicar la causa y el siguiente paso.

No llega nada (datagrams_in sigue en 0)

  • Lista allow. Un contador denied creciente indica que el switch no está en input.huawei.allow; el journal muestra el origen rechazado.
  • Firewall. firewall-cmd --zone=nsconv-exporters --list-all debe mostrar la red de los switches como origen y 9996/udp como puerto.
  • Puerto. La línea export host del switch debe indicar el puerto de input.huawei.listen. ss -ulnp | grep 9996 muestra que nsconv escucha.
  • Filtro de ruta inversa. Con rp_filter = 1 (estricto) el kernel descarta los paquetes que llegan por una interfaz que no es su ruta de vuelta al origen1. Revise sysctl net.ipv4.conf.all.rp_filter net.ipv4.conf.<interfaz>.rp_filter (se aplica el valor mayor). Con enrutamiento asimétrico, agregue una ruta a los switches por la interfaz receptora o use el modo flexible (2) en ella.
  • ¿Llega algo por el cable? nsconvctl debug-capture 198.51.100.21 captura lo que llega al equipo desde ese switch.

Datos sin plantilla (no_template, alerta no-template)

El switch envió datos antes de que nsconv tuviera su plantilla. Huawei refresca las plantillas cada 30 minutos por defecto; configure template timeout-rate 1 en el switch. Las plantillas aprendidas sobreviven a los reinicios de nsconv.

Tasa de muestreo desconocida (alerta sampling-default)

El switch no informa su tasa, así que se usa input.huawei.sampling_rate (por defecto 1000). Si el switch muestrea con otra tasa, defínala: nsconvctl config set input.huawei.sampling_override '{ "198.51.100.21" = 2048 }'. Use 1 para un switch sin muestreo.

Desfase de reloj (restamped, alerta restamped)

El reloj del switch difiere del equipo en más de convert.max_clock_skew_secs (300 s). Mientras tanto nsconv corrige los tiempos de los flujos. Corrija NTP y la zona horaria del switch; la columna SKEW muestra la diferencia medida.

FlowLink no muestra nada

  • remote_addrs. Con source_address = "exporter" debe listar las IP de los switches; con local, la dirección de nsconv (o 127.0.0.1 en el mismo equipo). FlowLink descarta los flujos de otros orígenes.
  • Parser y puerto. La salida IPFIX necesita un consumidor ipfix, NetFlow v9/v5 un consumidor netflow, en el puerto de output.<name>.target.
  • Colector caído. La alerta collector-down y la columna COLLECTOR de la salida indican que nada escucha en el puerto de destino en este equipo: inicie FlowLink o corrija el puerto.
  • Recién reiniciado. Tras reiniciar FlowLink espere hasta 20 segundos al siguiente refresco de plantillas.
  • Salida fallida: cannot open transparent sockets. Al servicio le falta CAP_NET_RAW, que la unidad incluida otorga. Restaure la unidad o configure source_address = "local".
  • Independiente a través de routers con exporter. Los routers descartan paquetes con las direcciones de los switches como origen; use local.

v5 e IPv6

NetFlow v5 no admite IPv6. Los switches con tráfico IPv6 deben exportar v9 (o IPFIX) con las líneas ipv6 netstream, y una salida de nsconv con protocol = "netflow5" descarta los flujos IPv6 (contador v6_on_v5). Use ipfix o netflow9.

Descartes del kernel en picos de tráfico

Un kernel_drops creciente en una entrada (o RcvbufErrors en grep ^Udp: /proc/net/snmp) indica que se llenó el búfer del socket. Compruebe que sysctl net.core.rmem_max sea al menos 8388608 y aumente input.huawei.recv_buffer_bytes si hace falta (reinicio).

El servicio no arranca: estado 203/EXEC

Etiqueta SELinux de un binario copiado a mano: restorecon -v /usr/local/bin/nsconvctl. Para otros errores de arranque, journalctl -u nsconv muestra el motivo; nsconvctl config check valida el archivo.
