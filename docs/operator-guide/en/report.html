Overview

What nsconv does

Huawei switches and routers export their flows as NetStream: NetFlow v5, NetFlow v9 or IPFIX with Huawei-specific details (a modified v5 version field, private fields, uptime-relative timestamps, long template refresh intervals, sampling rates that are often not reported). Illumio FlowLink reads NetFlow v5, v7, v9, IPFIX and sFlow1. nsconv sits between the two: it receives NetStream, decodes it with the Huawei details handled, and sends every flow again as clean, standard IPFIX (default), NetFlow v9 or NetFlow v5 to FlowLink.

Use nsconv when Huawei devices must feed Illumio FlowLink. It runs as a small service (nsconv.service) on the FlowLink host, or on its own host. One binary, nsconvctl, runs the service and is also the command-line tool and the terminal UI.

Data flow, co-located deployment (default)

What happens to each flow

  • Accepted only from allowed switches. Datagrams from sources outside the input's allow list are dropped and counted. An empty list drops everything.
  • Decoded with the Huawei details handled: v5 with the direction bit, v9 and IPFIX templates per switch, Line-card Source IDs, IPFIX uptime-relative times, repeated fields. Learned templates are saved, so a restart does not wait for the switch's next template refresh.
  • Re-sent with one fixed, standard template (IANA fields only, no padding, no vendor fields), absolute timestamps, the byte count, and the sampling rate in every record. Counters are not scaled: FlowLink receives the raw numbers and the rate.
  • Exporter identity kept. By default each switch's flows leave nsconv from that switch's own IP address and port, so FlowLink still sees every switch as its own sender.
  • Clock correction. If a switch clock is off by more than 5 minutes (time zone, missing NTP), flow times are shifted to the receive time so FlowLink does not discard them.
  • Everything is counted. Every dropped or changed flow has a named counter in nsconvctl status, the TUI and the journal.

Install

OPTION ARPM package (recommended)
INSTALL HOST (ROOT)
rpm -ivh nsconv-0.1.0~rc1-1.x86_64.rpm

The package creates the system user and group nsconv and installs these files. It does not enable or start the service and does not open any firewall port.

OPTION BStatic binary with nsconvctl install

For hosts where you prefer not to install an RPM. --dry-run prints every step first:

INSTALL HOST (ROOT)
chmod 0755 nsconvctl-0.1.0-rc1-x86_64-linux
./nsconvctl-0.1.0-rc1-x86_64-linux install --dry-run
./nsconvctl-0.1.0-rc1-x86_64-linux install

It copies the binary to /usr/local/bin/nsconvctl, creates the nsconv user and group, writes the unit to /etc/systemd/system/nsconv.service and the default configuration to /etc/nsconv/nsconv.toml (only if absent), and prints the firewall-cmd lines to run. --enable and --now also enable and start the service. The binary install does not ship the sysctl file; raise the kernel receive buffer limit yourself:

INSTALL HOST (ROOT)
echo 'net.core.rmem_max = 8388608' > /etc/sysctl.d/90-nsconv.conf
sysctl -w net.core.rmem_max=8388608

Firewall (firewalld)

Open the input port only for the switches, in a dedicated zone. The zone name and the network are examples:

INSTALL HOST (ROOT)
firewall-cmd --permanent --new-zone=nsconv-exporters
firewall-cmd --permanent --zone=nsconv-exporters --add-source=198.51.100.0/24
firewall-cmd --permanent --zone=nsconv-exporters --add-port=9996/udp
firewall-cmd --reload

When FlowLink runs on the same host and only nsconv should feed it, keep FlowLink's port (4739) closed to the network. Traffic from nsconv to FlowLink stays on loopback.

SELinux

No policy module is needed. A binary in /usr/bin or /usr/local/bin has the bin_t label and systemd runs it in the unconfined_service_t domain2. If you copy the binary by hand from another directory, restore its label; a wrong label shows as status 203/EXEC in systemctl status nsconv:

INSTALL HOST (ROOT)
restorecon -v /usr/local/bin/nsconvctl

Configure nsconv

Configure nsconv

The configuration is one TOML file, /etc/nsconv/nsconv.toml, with one [[input]] (where the switches send) and one or more [[output]] (where the flows go). The shipped file has one input named huawei and one output named flowlink; keys are addressed as input.huawei.allow, output.flowlink.target and so on. The full key list is in the Reference section.

nsconvctl config set changes one value, keeps the comments in the file, validates the result, writes it and asks the running service to reload. An invalid value is refused and the file stays untouched.

FIRST STARTThree settings, then start
1

Allow the switches

Single IPs or CIDRs. Until this is set, every datagram is dropped.

ROOT
nsconvctl config set input.huawei.allow '["198.51.100.0/24"]'
2

Point the output at FlowLink

The default is FlowLink's IPFIX consumer on the same host. For a FlowLink on another host use its address, for example 192.0.2.10:4739.

ROOT
nsconvctl config set output.flowlink.target 127.0.0.1:4739
3

Start the service and check it

Health ok and growing flows_out mean flows are leaving nsconv.

ROOT
systemctl enable --now nsconv
nsconvctl status

Common changes

GoalCommand (root)
Several switch networksnsconvctl config set input.huawei.allow '["198.51.100.0/24", "203.0.113.5"]'
Switches sample at 1:2048 but do not report itnsconvctl config set input.huawei.sampling_rate 2048
One switch samples differentlynsconvctl config set input.huawei.sampling_override '{ "198.51.100.21" = 2048 }'
Send NetFlow v9 instead of IPFIXnsconvctl config set output.flowlink.protocol netflow9
Keep one copy of transit trafficnsconvctl config set convert.direction ingress
Accept IPv6 switches toonsconvctl config set input.huawei.listen '[::]:9996', then systemctl restart nsconv

Counters are never scaled: nsconv forwards the raw numbers plus the rate. Precedence per switch: sampling_override, the rate the switch reports, then sampling_rate (default 1000).

Reload or restart

config set reloads by itself. After editing the file by hand, or with nsconvctl config edit ($EDITOR on a validated copy), run nsconvctl reload. Changing an input's listen address or receive buffer, adding or removing an input, or the [daemon] section needs systemctl restart nsconv; the reload answer says restart required. nsconvctl config check validates a file without applying it.

A second output

Outputs are added in the file. Example: also send NetFlow v9 to a second collector (name and address are examples):

/etc/nsconv/nsconv.toml
[[output]]
name = "collector2"
protocol = "netflow9"
target = "192.0.2.20:2055"
source_address = "local"

Configure FlowLink

Configure FlowLink

FlowLink reads /etc/illumio-flowlink/config.yaml1. Add one consumer for nsconv: an ipfix parser with a udp connector on the port of output.flowlink.target. remote_addrs is optional, takes single IP addresses (no CIDR) as a string or a list, and limits the consumer to those sources2,3.

Co-located, source_address = "exporter" (default)

FlowLink sees the switches as senders, so remote_addrs lists the switch IPs (examples):

/etc/illumio-flowlink/config.yaml
consumers:
  - name: nsconv-ipfix
    parser:
      type: ipfix
    connectors:
      - type: udp
        properties:
          ports: '4739'
          remote_addrs: '198.51.100.21,198.51.100.22'

source_address = "local"

FlowLink sees nsconv as the only sender. Co-located: remote_addrs: '127.0.0.1'. Standalone: the nsconv host's IP address, for example remote_addrs: '192.0.2.30'.

NetFlow v9 or v5 output

With protocol = "netflow9" or "netflow5" use a consumer with parser: type: netflow on its own port (for example 2055) and set output.flowlink.target to that port. Keep one protocol per consumer and port.

Apply the change by restarting FlowLink1:

FLOWLINK HOST (ROOT)
systemctl stop illumio-flowlink
systemctl start illumio-flowlink
After a FlowLink restart
nsconv resends its templates every 20 seconds (template_refresh_secs). A collector that starts after nsconv decodes the flows from the next template refresh on.

Which NetStream version on the switch

Switch trafficSwitch exportnsconv output
IPv4 onlyNetFlow v5 is enough; v9 also worksipfix (default)
IPv4 and IPv6NetFlow v9 (or IPFIX), plus the ipv6 netstream lines; NetStream v5 cannot carry IPv6ipfix or netflow9; never netflow5

Set input.huawei.sampling_rate (or sampling_override per switch) to the rate configured on the switches; v5 switches usually do not report it.

Configure Huawei

Configure the Huawei switches

Device-side commands: verify on your VRP release
The lines below are run on the Huawei device, not on the Linux host. Command syntax differs between product families and VRP releases; check each line against the command reference of your model and release before applying it.

Recommendations for every family: send to the nsconv host (example 192.0.2.10) on UDP 9996; refresh templates every minute (template timeout-rate 1); age flows quickly (timeout active 1, timeout inactive 15), otherwise long flows reach FlowLink up to 30 minutes late; use 32-bit interface indexes (index-switch 32); sample inbound only, so transit traffic is not reported twice; keep the device clock on NTP with the correct time zone. The default active timeout is 30 minutes and the default template refresh is 30 minutes1. Example values: switch address 198.51.100.21, interfaces GigabitEthernet0/0/1 and 10GE1/0/1, record name illumio-rec, slot 3.

S-series / AR (V200 style): NetFlow v9 original flows

HUAWEI DEVICE — VERIFY ON YOUR VRP RELEASE
ip netstream export version 9
ip netstream export source 198.51.100.21
ip netstream export host 192.0.2.10 9996
ip netstream export template timeout-rate 1
ip netstream export template option sampler
ip netstream export index-switch 32
ip netstream timeout active 1
ip netstream timeout inactive 15
#
interface GigabitEthernet0/0/1
 ip netstream sampler fix-packets 1000 inbound
 ip netstream inbound

For IPv4-only switches export version 5 is also fine. On AR routers an unset sampler means 1:100 by default. Where IPv6 must be visible, add the matching ipv6 netstream lines (same keywords, as in the NetEngine example) and keep version 9.

CloudEngine (V200R019C10 syntax): NetFlow v9 flexible record

HUAWEI DEVICE — VERIFY ON YOUR VRP RELEASE
netstream export ip source 198.51.100.21
netstream export ip host 192.0.2.10 9996
netstream export ip version 9
netstream export ip index-switch 32
netstream export ip template timeout-rate 1
netstream timeout ip active 1
netstream timeout ip inactive 15
#
netstream record illumio-rec ip
 match ip source-address
 match ip destination-address
 match ip source-port
 match ip destination-port
 match ip protocol
 match ip tos
 collect counter bytes
 collect counter packets
 collect interface input
 collect interface output
#
interface 10GE1/0/1
 netstream record illumio-rec ip
 netstream inbound ip

Bind the record to the interface before enabling NetStream on it. Some releases write the refresh line as netstream template ip timeout 1.

Operate

Operate

Status

nsconvctl status shows health and its reasons, open alerts, inputs, counters (zero drop counters are hidden), one line per exporter session and one per output. --exporter 198.51.100.21 narrows it to one switch, --detail adds the busiest interfaces and idle sessions, --json prints the full status as JSON. Every command ends with a machine-readable NSCONV-RESULT line and an exit code (Reference section). The exporters table has one row per exporter session with the columns EXPORTER (switch IP and source port), SOURCE-ID, VER (v5, v9, ipfix), INPUT, SAMPLING (rate and its source: override, reported by the switch, or default), SKEW (switch clock minus host clock), RESTAMPED, FLOWS, NO-TPL, LAST SEEN and SEQ LOSS (loss estimated from the switch's sequence numbers).

Alerts

Conditions that need a look raise an alert with a stable id: sampling-default, restamped, no-template, seq-gap (sequence numbers show loss), many-sessions, flowless-sessions and collector-down (nothing listens on a local output target). Once you have checked one, silence it; it comes back if its value doubles or after it has been absent for 24 hours. Dismissing never changes the health.

ROOT OR GROUP NSCONV
nsconvctl dismiss sampling-default:198.51.100.21:40000:0
nsconvctl dismiss all
nsconvctl undismiss sampling-default:198.51.100.21:40000:0

Logs

nsconv logs to the journal; journald handles rotation. At info nothing is logged per datagram; repeated conditions are rate limited, and persistent ones (default sampling rate, clock skew, data without template) warn once per exporter every 6 hours.

ROOT OR GROUP NSCONV
nsconvctl logs -f                # follow (journalctl -u nsconv -f)
nsconvctl logs --since 2h
nsconvctl logs --recent 50       # last lines from the service's memory
nsconvctl config set log.level debug   # one line per event kind, rate limited (root)
nsconvctl config set log.level info

Capture one switch for analysis

nsconvctl debug-capture 198.51.100.21 runs tcpdump (root) for up to 60 seconds or 2000 datagrams and writes the switch's raw NetStream datagrams to a pcap file; --dry-run prints the tcpdump command. nsconvctl decode <file.pcap> shows the flows nsconv reads from it, on any host.

Upgrade

RPM: rpm -Uvh with the new package, for example rpm -Uvh nsconv-0.1.1-1.x86_64.rpm. The upgrade keeps /etc/nsconv/nsconv.toml and the learned templates and restarts the service if it was running. Binary install: run install --now with the new binary.

Uninstall

RPM: rpm -e nsconv stops and disables the service and removes the files; the nsconv user, /var/lib/nsconv and a modified configuration (nsconv.toml.rpmsave) are kept. Binary install: nsconvctl uninstall, or nsconvctl uninstall --purge to also remove /etc/nsconv, /var/lib/nsconv and the user and group.

TUI tour

nsconvctl tui is a full-screen terminal view of the running service: the status refreshes every second. Troubleshooting

Troubleshooting by symptom

Start with nsconvctl status: health reasons, alerts and non-zero drop counters usually name the cause and the next step.

Nothing arrives (datagrams_in stays at 0)

  • Allow list. A growing denied counter means the switch is not in input.huawei.allow; the journal names the denied source.
  • Firewall. firewall-cmd --zone=nsconv-exporters --list-all must show the switch network as a source and 9996/udp as a port.
  • Port. The switch's export host line must name the port of input.huawei.listen. ss -ulnp | grep 9996 shows that nsconv listens.
  • Reverse-path filter. With rp_filter = 1 (strict) the kernel drops packets that arrive on an interface that is not its route back to the source1. Check sysctl net.ipv4.conf.all.rp_filter net.ipv4.conf.<interface>.rp_filter (the higher value applies). With asymmetric routing, add a route to the switches via the receiving interface or use loose mode (2) on it.
  • Is anything on the wire? nsconvctl debug-capture 198.51.100.21 captures what reaches the host from that switch.

Data without template (no_template, alert no-template)

The switch sent data before nsconv had its template. Huawei refreshes templates every 30 minutes by default; set template timeout-rate 1 on the switch. Learned templates survive nsconv restarts.

Sampling rate unknown (alert sampling-default)

The switch does not report its rate, so input.huawei.sampling_rate (default 1000) is used. If the switch samples at another rate, set it: nsconvctl config set input.huawei.sampling_override '{ "198.51.100.21" = 2048 }'. Use 1 for an unsampled switch.

Clock skew (restamped, alert restamped)

The switch clock differs from the host by more than convert.max_clock_skew_secs (300 s). nsconv shifts the flow times meanwhile. Fix NTP and the time zone on the switch; the SKEW column shows the measured difference.

FlowLink shows nothing

  • remote_addrs. With source_address = "exporter" it must list the switch IPs; with local the nsconv address (or 127.0.0.1 on the same host). FlowLink discards flows from other sources.
  • Parser and port. IPFIX output needs an ipfix consumer, NetFlow v9/v5 a netflow consumer, on the port of output.<name>.target.
  • Collector down. The collector-down alert and the output's COLLECTOR column mean nothing listens on the target port on this host: start FlowLink or fix the port.
  • Just restarted. After a FlowLink restart allow up to 20 seconds for the next template refresh.
  • Output failed: cannot open transparent sockets. The service lacks CAP_NET_RAW, which the shipped unit grants. Restore the unit, or set source_address = "local".
  • Standalone across routers with exporter. Routers drop packets with the switch addresses as source; use local.

v5 and IPv6

NetFlow v5 has no IPv6. Switches with IPv6 traffic must export v9 (or IPFIX) with the ipv6 netstream lines, and an nsconv output with protocol = "netflow5" drops IPv6 flows (counter v6_on_v5). Use ipfix or netflow9.

Kernel drops at traffic peaks

A growing kernel_drops on an input (or RcvbufErrors in grep ^Udp: /proc/net/snmp) means the socket buffer filled up. Check that sysctl net.core.rmem_max is at least 8388608 and raise input.huawei.recv_buffer_bytes if needed (restart).

Service does not start: status 203/EXEC

SELinux label of a hand-copied binary: restorecon -v /usr/local/bin/nsconvctl. For other start errors, journalctl -u nsconv shows the reason; nsconvctl config check validates the file.

Exit codes

Every command except run, tui and logs -f ends with NSCONV-RESULT schema=1 version=… command=… code=… status=… (on stderr with --json).

CodeStatusMeaning
0okSuccess.
1warningDone with a warning, e.g. health degraded.
2failureFailed: daemon not running, invalid config, send error.
3failureUsage error: bad arguments, unreadable file.
4failurePermission denied: run as root or as a member of group nsconv.
128+N—Killed by signal N (e.g. 130 for Ctrl-C).
