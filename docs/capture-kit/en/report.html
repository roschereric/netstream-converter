Overview

Overview

To plan the integration of your Huawei switches with Illumio, we need to see what the switches really export. This kit shows you how to collect that evidence with three items: a short network capture, the output of a few display commands, and a short questionnaire. Nothing is installed or changed on the switches, except one optional setting described in Part 1.

What you collect and where it goes

What the evidence answers

  • Whether the switches export IP flows (IPv4/IPv6 addresses and ports) or only Layer 2 (MAC/VLAN) flows.
  • Which NetStream version each switch uses, and whether IPv6 NetStream is configured.
  • Whether a sampling rate is configured and whether the flows report it.
  • Which line cards or stack members export, how often templates are refreshed and from which UDP source port.
  • Whether the clock, time zone and NTP of each device are correct.
  • The exact model and software version of each switch.

What you will need

  • A Linux host that receives the NetStream packets (the current collector, or any host that can see the traffic), with tcpdump and administrator rights.
  • Read access to each switch (console or SSH) to run display commands.
  • About one hour in total. The capture runs in the background while you collect the command output.

Capture

Part 1: Capture the NetStream traffic

NetStream is sent by the switch as UDP packets to your collector. Recording those packets on the receiving host shows us exactly what each switch exports. The packets contain flow summaries only (addresses, ports, protocol and counters), not the content of your traffic.

1

Note the values you will use

The network interface of the receiving host that sees the NetStream packets, and the management or source IP address of each switch. Run date -u on the host and write down the result: we compare it with the switch clock.

2

Start the capture

Use one file per switch, or one file for all switches (see the second command). Stop with Ctrl+C, or use the timeout form so that it stops by itself.

CAPTURE HOST (LINUX)
# One switch. Replace the values in angle brackets.
sudo tcpdump -i <interface> -s 0 -nn -w netstream.pcap udp and host <switch-ip>

# Several switches in one file, stops by itself after 40 minutes (2400 s).
sudo timeout -s INT 2400 tcpdump -i <interface> -s 0 -nn -w netstream.pcap \
  udp and '(host <switch-1-ip> or host <switch-2-ip>)'
3

Make sure the capture includes the templates

Version 9 switches describe their records in a template that is sent only from time to time. Without it the records cannot be read. Choose one option.

OptionWhat to do
A. Longer capture (no change on the switch)Capture for 40 minutes, so the capture covers the default template refresh of 30 minutes1.
B. Shorter refresh (if your change process allows it)Set the template refresh to 1 minute during the capture, capture for 15 minutes, then restore your previous value. S-series and AR: ip netstream export template timeout-rate 1. CE: netstream export ip template timeout-rate 1. Use ? to confirm the command name on your software release.
C. Capture at export startIf you enable NetStream export or restart it during a maintenance window, start the capture just before. Switches send their templates when export starts.
4

Check the file

List the first packets. You should see UDP packets from the switch IP address to your collector. Many Huawei switches send from UDP source port 400001. If the file is empty, check the interface name, the switch IP address and any firewall between the switch and the host.

CAPTURE HOST (LINUX)
tcpdump -nn -r netstream.pcap -c 5
No access to the receiving host?
Use port mirroring (SPAN) on the switch port that connects to the collector, and send the mirrored traffic to a Linux host running the same tcpdump command on the mirror interface. Use your standard procedure for port mirroring.
Sources
  1. Huawei NetStream YANG module (template refresh 30 min, source port 40000) — netconfcentral.org/modules/huawei-netstream/2019-06-27
  2. tcpdump manual — tcpdump.org/manpages/tcpdump.1.html
Switch Commands

Part 2: Collect the switch information

Run the commands below on each switch while the capture is running. Save the output of each switch in one text file (for example with your terminal's session log). If a command is not recognized on your software release, type the start of it followed by ?, use the closest match and continue with the next one.

2.1 Model, software and line cards

SWITCH CLI
screen-length 0 temporary
display version
display device

2.2 Clock, time zone and NTP

Run display clock at the moment you run date -u on the capture host, or note both times. Use the NTP command that your software accepts: ntp-service on S-series and AR, ntp on CE.

SWITCH CLI
display clock
display ntp-service status
display ntp-service sessions
# CE software:
display ntp status
display ntp sessions
display current-configuration | include clock
display current-configuration | include ntp

2.3 NetStream configuration

SWITCH CLI
display current-configuration | include netstream
display current-configuration | include sampler

The interface lines (for example ip netstream inbound or netstream inbound ip) appear under their interface in the full configuration. If you may share the complete configuration, add the output of display current-configuration. Otherwise run display this inside each interface view that carries NetStream and include the interface name.

2.4 NetStream status and statistics

List the NetStream display commands of your release, then run the ones for statistics and for the flow cache and add their output.

SWITCH CLI
display ip netstream ?
# CE software:
display netstream ?

What we look for in the configuration

If the output showsIt tells us
export version 5, 9 or ipfixThe NetStream version in use
Lines that start with ipv6 netstreamIPv6 NetStream is configured
Lines that mention ethernetLayer 2 (Ethernet) flows are configured
sampler linesSampling mode, rate and direction
template timeout-rate and template optionTemplate refresh and option templates
export source and export hostExport source address, collector address and port
slot lines and the display device outputLine cards and stack members that export

Return Files

Part 4: Name and send the files

File names

Use this pattern, in lowercase and without spaces: <site>_<switch>_<content>_<yyyymmdd>.<ext>. The names below are examples.

File (example names)Content
site-example_tor-sw-example-01_netstream_20261105.pcapCapture from Part 1
site-example_tor-sw-example-01_display_20261105.txtCommand output from Part 2
site-example_questionnaire_20261105.txtAnswers from Part 3

Package and send

Put all files in one folder, compress it and create a checksum so that we can confirm the file arrived intact.

CAPTURE HOST (LINUX)
tar -czf site-example_netstream-kit_20261105.tar.gz site-example/
sha256sum site-example_netstream-kit_20261105.tar.gz

Send the archive and the checksum line to the Illumio contact who gave you this kit.

Share through your approved channel
The capture contains the internal IP addresses of your servers and network devices, and the command output contains device names and addresses. Send the files through the file-sharing channel that your organization approves for this kind of data. The filtered commands in this kit do not output passwords or keys; review the files before sending if you added the full configuration.

Final checklist

  • Capture file — one file per switch, or one file with all switches, at least 15 minutes with templates, or 40 minutes.
  • Command output — one text file per switch with the commands of Part 2.
  • Questionnaire — answers for each switch and the general questions.
  • Times — the host date -u value and the display clock value of each switch.
  • Package — archive and checksum sent through the approved channel.
